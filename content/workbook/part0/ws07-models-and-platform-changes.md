# WS 0.7. Models and platform changes

A dated table of the current models and which to use for what, a one-page change log you'll keep, and the hour-long re-test routine for the day a new model lands. Thirty minutes to set up; an hour each time it's needed.

## Why this matters

Chapter 11 said the platform moves. This is the page that keeps you standing when it does.

Three things on it. A table of today's models, dated, so you know what you're choosing between and which to pick for which work. A change log, which is a half-page file you add a line to whenever the tool changes under you. And the re-test routine: the hour you spend after a release running your most-used skills against a real task and comparing to the last thing you approved, so drift gets caught by you, on purpose, instead of by a reader, by accident.

None of this is technical. The hardest part is remembering to do it, which is why the log has a date column and the first line in it is today.

## Mark's example

My log started after the first time a release broke a skill without telling me. My column skill, tuned over months, started producing longer paragraphs and a phrase I'd never had to ban before. It took me a day to work out that the model had changed and my file hadn't. The log is three lines per release now: date, model, what I changed. I've been glad of it every time.

The re-test is an hour. Three skills (column, voice pass, deck), one real task each, compare to the last version I approved. If something drifted, fix the file, not the draft. Read the release notes for anything about writing style or tools. Log it. Since the Logitech years, when every operating-system release meant re-testing every product, I haven't found a better routine than test before, test after, write down what moved.

Which model for what, as I do it today: the strongest for anything with a reader who matters or a judgment call in it; a faster tier for summaries, sorting, and first passes I'll check anyway. A good brief outranks the tier. The weak model with four hundred words of context beats the strong one with four.

## Why this compounds

Every release after this one costs you an hour instead of a lost week, and the log turns each change into a line you can read back when a draft feels off. Your skills (Part B) survive because you re-test them; your voice (Part A) stays yours because drift gets caught the week it happens, not the month after.
