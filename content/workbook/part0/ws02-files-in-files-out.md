# WS 0.2. Files in, files out

Attach a document, paste a passage, and download a result, so you know what the tool can read and what it can hand back. Fifteen minutes.

## Why this matters

Most of the useful work in the book starts with the tool reading something you already have: a report, a deck, a spreadsheet, a photo of a whiteboard. And most of it ends with the tool handing you something you can open somewhere else. If you've only ever typed into the box and read what came back, you've used about a third of what's there.

The habit is small: attach the thing instead of describing it. People describe a spreadsheet in three paragraphs when they could attach it in one click, and the description is always worse than the file. The tool reads PDFs, Word documents, spreadsheets, plain text, and images, and it reads them well enough to quote a page number back to you.

The other half is getting things out. A draft that lives only in the chat is a draft you'll lose. A draft downloaded as a file is yours.

## Mark's example

The investor deck morning in Chapter 10 started with four files attached: our full company overview, a shorter deck from the week before, an advisor deck, and a PDF of an older investor deck. The tool read all four and built from them. It also read the speaker notes inside one of them, which is how it caught a slide that should never have gone outside the company. I'd have missed that. The notes were in the file; I'd attached the file; it read the whole file.

Going out, the deck came back as both a PowerPoint and a PDF, and I checked the rendered PDF before anything went anywhere, because the rendered file is what the reader sees and the chat's description of it is not.

The thing I didn't know in my first year: it reads images. A photo of a whiteboard after a meeting, attached, comes back as a typed list of what was on the board. I use that most weeks now.

*How to: attaching and downloading, as of October 20, 2026. In the chat box there's a "+" (or a paperclip) for attaching files; you can also drag a file onto the chat or paste text directly. The tool reads PDFs, Word documents, spreadsheets, plain text, code, and images, within size limits that change; if a file is refused, split it or paste the part you need. Anything it builds opens in a panel beside the chat; documents and decks there have an Export control, and legacy outputs have a download control at the top of the panel; both are also saved to the Artifacts tab in the sidebar. Creating files requires "Code execution and file creation" to be on under Settings > Capabilities. All plans can attach files and create them.*

## Why this compounds

Every worksheet in Part B starts by attaching something real: last week's report, your brand guide, a draft. Once attaching is a reflex, the tool is working on your actual material instead of your description of it, and every skill you build in Part B is tested on real files from day one.
