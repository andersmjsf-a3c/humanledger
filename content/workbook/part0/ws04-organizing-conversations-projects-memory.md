# WS 0.4. Organizing conversations, projects, and memory

Start a conversation on purpose, make one project, and see what memory carries between rooms, so you know where everything you tell the tool ends up. Thirty minutes.

## Why this matters

A conversation is a room, and nothing follows you out unless you've set up something to carry it. Three things can. Memory carries what's true about you. A project carries what's true about one body of work. A skill carries how to do one kind of task. This page sets up the first two. Part B sets up the third.

Three sorting questions are the whole method. Is this true about me regardless of what I'm working on? Memory. Is this about one body of work, and only that? The project. Is this about how to do one kind of task, wherever it comes up? A skill. Ask those three questions every time you're about to tell the tool something you'll want it to keep, and you'll never explain yourself from scratch again.

The trap is treating them as the same thing. Project facts in memory means every conversation about dinner knows about your Q3 pipeline. Personal preferences in a project means you repeat them in the next project. Sort first.

## An example

*An illustration, not a real person.* Say you manage a sales team of eight. Your memory holds who you are and how you like work done: your role, that you want the number before the narrative, that you never want bullet points in anything going to your VP, that every deal gets a date. Each of those started as a correction in a conversation and crossed over when you'd said it more than once in more than one room.

You keep two kinds of things out. Anything a stranger shouldn't see on a screen, and anything about other people that's theirs. Memory is for durable, shareable facts about how you work. It isn't a diary.

Your projects are rooms with furniture. The pipeline project's instructions say what the weekly summary is for and who reads it; its files are the current pipeline export, the territory map, and the skill that drafts the Monday summary. Open a conversation inside it and the tool already knows all of that. The hiring project has different furniture. When something from one belongs in the other, you carry it across on purpose, as a file.

*How to: memory and projects, as of October 26, 2026, from the Claude help center. Memory: Settings > Your Claude (older layout: Settings > Memory, "Generate memory from chats"). Everything it remembers is listed under Topics (Settings > Your Claude > Manage); select one to read, edit, or delete it, or tell the tool in a chat to remember, change, or forget something. Sensitive topics are excluded unless you turn on "Include sensitive topics in memory." To keep one chat out of memory, click "+" in a new chat and turn off Memory before the first message, or use an incognito chat. Turning memory off offers a pause (keeps what's saved, stops adding) or "Reset memory" (deletes everything, including project memories, permanently). Memory is on by default for Free, Pro, and Max; on Team and Enterprise an owner must enable it first. Each project has its own memory plus your account memory; "Use account memory" on the project page turns the account part off for that project. Projects: Projects in the left sidebar, "+ New Project," name and describe it, then set project instructions and add files under project knowledge; any chat started inside the project uses both. Free accounts get five projects; paid plans, unlimited. Past-chat search ("Search and reference chats" under Settings > Your Claude) is on paid plans only.*

## Why this compounds

The fact you gave memory in question 2 is the first line of Worksheet A1, and the project you made in question 4 is where every Part B skill gets tested. From here on, each conversation starts closer to where the last one ended, and the explaining you did this week is explaining you won't do next week.
