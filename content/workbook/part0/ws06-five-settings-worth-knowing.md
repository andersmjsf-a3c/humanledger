# WS 0.6. Five settings worth knowing

A dated table of the five settings that change what the tool does for you, checked once so you stop wondering why it behaved differently today. Ten minutes.

## Why this matters

Most of what people blame on the tool is a setting. It didn't search the web because it decided not to, or search was off for that chat. It didn't remember because memory was paused. It gave a shallower answer because a faster model was selected. It couldn't make a file because file creation wasn't turned on. None of those is the tool being bad at the job. All of them are a switch.

Five settings account for nearly every "it worked yesterday," so this page is a table and a check. Go through it once. Then, when something behaves oddly, come back here before you blame yourself or the machine.

These move. The table has a date on it. If the date is old, the names may have changed; the setting itself almost certainly still exists, so check the Where things live page, or ask the tool where it is now.

## An example

*An illustration, not a real person.* Say you're a first-year founder and the setting that cost you the most was web search. You'd ask for a market figure, get a confident number, and only later work out that the number came from the model's memory of the world, with the world itself never consulted. Now, when a fact matters, you ask it outright to search and to cite, and the fact pass in Part B assumes it did.

The one you changed most recently was model choice. For three months you ran the strongest model for everything. You still do for judgment work: the pitch, the pricing argument, anything with a reader who matters. For routine summaries you've moved down a tier, because the wait and the usage limit started to cost more than the difference in quality. The right setting changes with the job in front of you.

## Why this compounds

You've turned five mysteries into five known switches. From now on, a strange answer costs you thirty seconds of checking instead of an afternoon of doubt, and when the next change arrives, you'll know which switch to look for instead of relearning the tool.
