# WS 0.5. Artifacts and outputs

Edit, save, and share one thing the tool built for you, and know where a skill lives once you've written one, with the no-setup fallback that works everywhere. Twenty minutes.

## Why this matters

When the tool makes something substantial (a document, a page, a deck, a small tool), it doesn't put it in the chat. It opens it in a panel beside the chat, saves it, and lets you come back to it, change it, and share it. The help pages call these artifacts. Most people call them "the thing it built," because that's what they are.

Two habits here. First: anything you'll keep, you edit in the panel and export, because the rendered file is what a reader sees and the chat's description of it is not. Second: a skill you've written (Part B) has to live somewhere the tool will load it. There's a proper place, and there's a fallback that works on every plan with no setup, and you should know both, because the proper place has moved more than once and will again.

## An example

*An illustration, not a real person.* Say you run a two-person accounting practice and you've asked for a client-facing one-pager on a rule change. It comes back as an artifact: a document in a panel beside the chat. You fix two sentences directly in the panel, then export the PDF to send and keep the Word file as the source. Both are in the Artifacts tab if you need them next quarter, and you will, because the same rule comes up with every new client.

Your skills live in two places. The saved version is uploaded under Customize > Skills, where the tool loads it whenever you name the task. The source is the .md file in your skills folder on your own computer, and that's the one you edit, because the file is yours and the upload is a copy. When a skill changes, you upload the new version and the old one is gone. Before you had saved skills, you pasted the instructions at the top of every conversation, which is slower and works exactly as well. If the upload button moves tomorrow, pasting still works.

*How to: artifacts and skills, as of October 26, 2026, from the Claude help center. Artifacts open beside the chat and are saved to the Artifacts tab in the sidebar; they start private; they're available on every plan. Document, deck, and design artifacts have an Export control (documents to Word, PDF, Markdown, or Google Docs; decks to PowerPoint or PDF; designs to zip, PDF, PowerPoint, or HTML). In a document, highlight text and choose "Edit with Claude" to change a passage. Creating artifacts requires "Code execution and file creation" on under Settings > Capabilities. Skills: put your `SKILL.md` in a folder named for the skill, zip the folder, go to Customize > Skills, click "+", then "+ Create skill," then "Upload a skill." Each skill has an on/off toggle there. Skills upload on every plan and need code execution turned on. If an upload fails, the usual reasons are a folder name that doesn't match the skill name, a missing `SKILL.md`, or an odd character in the name. The fallback, pasting the file at the top of a conversation, needs nothing.*

## Why this compounds

You now have the two moves every later worksheet assumes: get the rendered thing out before you ship it, and put a skill where the tool loads it without being asked. Part B's first worksheet ends with you uploading a real skill using exactly step 5, and the re-test routine in Worksheet 0.7 assumes you know where your skills live.
