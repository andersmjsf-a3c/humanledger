# WS B1. Your first skill

The thing you do every week, written down once. When you finish this page you'll have one working skill for a task you repeat, tested on a real week. About an hour.

## Why this matters

The rule is simple: explain something to it three times and it's time to write it down. This page is where you write it down.

Pick a task with a shape. Something you do every week or every month, that has the same parts each time, and that you do in your own particular way. The weekly report. The client proposal. The summary after every meeting. The post you write every Friday. If you're stuck, ask yourself what you'd hand to someone covering for you on vacation, and what you'd have to explain so they didn't embarrass you.

Don't pick the hardest job you have. Pick the one you do most. The first skill teaches you how skills work, and you learn fastest from the one you'll run every week.

Three things to expect, overstated on purpose so you don't quit in week two. The first version will be wrong in ways you can't see until you use it. The first result will need real editing, not a polish. And you'll be changing the file as often as you use it for a while, which feels like failure and is the process. Most people rebuild their first skill many times in its first two months. The box at the bottom of this page is where that work goes.

## An example

*An illustration, not a real person.* A sales manager's first skill, for the Monday pipeline summary to the VP, condensed. The full version runs two pages; this is what it looks like with the specifics trimmed so you can see the bones.

```
# Skill: Monday summary
This skill serves [the manager]. Use it whenever I say "Monday summary."

## What this task is
A one-page pipeline update for my VP, every Monday. Done means: the
number against target first, what moved, what's at risk, what I need
from her. She reads it in three minutes on her phone.

## Inputs I'll give you
- The pipeline export (CSV)
- My notes from the week, rough
- Which deals I already discussed with her (so you don't repeat them)

## Steps
1. Open with the number against target, one line.
2. What moved since last Monday: closed, advanced, slipped. Dates on every deal.
3. What's at risk, with why, in one line each.
4. What I need from her, as a question she can answer yes or no.
5. Stop. No summary paragraph.

## Output
Plain text I can paste into email. Under 250 words. No bullets.

## Rules
- A date on every deal. Always.
- Never the words "robust," "leverage," or "circle back."
- Never a deal I haven't put in the export.
- If a number in my notes disagrees with the export, ask; don't pick one.
```

Half of that rules section is the corrections log from Worksheet A4, moved into a file so it never gets typed again. Most of those lines weren't in version one. They arrived one at a time, each after a draft that got it wrong.

## Your turn

Fill these in. Write in plain sentences, the way you'd explain it across a desk. Each answer has a length beside it so you know when you're done.

1. **The task, in one sentence.** What is it, and how often do you do it?
   _____

2. **The words you'll use to ask for it.** Two or three. ("Weekly update." "Draft the recap.")
   _____

3. **What it is and who it's for.** One paragraph. Who reads it, what they need from it, what "done" looks like.
   _____

4. **What you'll hand it every time.** A list of two to five things. Files, numbers, notes, links.
   _____

5. **The steps.** Three to six, in the order you'd do them yourself. Short.
   _____

6. **What the result looks like.** Be exact: length, format, what comes first, what kind of file or message.
   _____

7. **Always.** Two to four things that must be true of every result.
   _____

8. **Never.** Two to four things that must not appear. Start with anything it's done before that made you wince.
   _____

9. **Ask me before guessing.** One or two things it should check with you rather than assume.
   _____

Now paste the frame below into a conversation with your answers filled in, and ask it to tidy the wording without changing the meaning. Save what comes back as a file named for the task.

```
# Skill: [answer 1]
This skill serves [your name]. Use it whenever I say "[answer 2]".

## What this task is
[answer 3]

## Inputs I'll give you
[answer 4]

## Steps
[answer 5]

## Output
[answer 6]

## Rules
[answer 7, each on its own line]
[answer 8, each on its own line]
[answer 9, each on its own line]
```

**Test it once.** Open a fresh conversation. Paste the skill at the top (or load it, if your setup saves skills; Part 0 covers both). Hand it this week's inputs and say the words from answer 2. Read the result next to what you'd have done by hand. Write down the three biggest differences.

## Version 2, after a week of real use

A skill is never finished. Come back to this box after you've run the skill on two or three real weeks and answer:

- What did it get wrong that you corrected by hand? (Each one goes into Rules.)
- What did you find yourself explaining in the conversation that should have been in the file? (Goes into Steps or Inputs.)
- What did it do that you liked and hadn't asked for? (Make it a rule so it keeps doing it.)
- What's one thing in the file that turned out not to matter? (Cut it.)

Make the changes. Rename the file with a version number if that helps you keep track. That's version 2, and it's where the compounding starts to show.

## Why this compounds

Every correction you put in this file is one you'll never make again, on a task you do every week. The first version saves you the setup. The fifth version, carrying months of corrections, hands you a first draft that's mostly right before you've read it. And the shape you just learned is the shape of every skill you'll ever build, so the second one takes half the time of the first.
