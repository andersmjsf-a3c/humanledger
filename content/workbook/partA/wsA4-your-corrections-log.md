# WS A4. Your corrections log

A running list of the corrections that must stick, with the first five filled in and a rule for when a correction graduates into memory or a skill. Twenty minutes to start; two minutes a week after.

## Why this matters

Chapter 2's whole argument fits in one line: every correction you keep is one you never make again. The keeping is the part people skip. They correct the tool in the moment, it holds for the conversation, and the next conversation makes the same mistake (Chapter 11 explained why: a conversation is a room). The log is where the correction goes so it survives the room.

It's a file. One line per correction: what it did, what it should do instead, the date. Nothing else. After a month you'll have twenty lines and you'll notice three things about them: the same correction appears more than once, some of them are about you regardless of the task, and some are about one kind of work. That's the sorting from Chapter 12, and the log is where it happens.

I didn't set out to build a list. I set out to fix one sentence in one draft. The list is longer now, and every item on it started as a second message.

## Mark's example

The first entries in mine, from memory, with the dates approximate.

| Date | What it did | What it should do | Where it went |
|---|---|---|---|
| Early 2026 | Wrote "I want to be honest with you" in a column draft | Never. Say the thing. | Memory, then the voice skill |
| Spring 2026 | Implied I'd worked at Google | I built a partnership with Google, from RAPT. I never worked there. | Memory, and every book skill |
| Sept 2026 | Wrote "100+ partnerships" | "Hundreds of partnerships." | Memory |
| Sept 2026 | Em dashes in everything | None. Commas, periods, colons, parentheses. | Memory, voice skill, the linter |
| Oct 2026 | "Thirty years using computers" | "Close to fifty years." | The book skills |
| Oct 2026 | Named an investor in a chapter | No names of investors, prospects, customers, or colleagues. Roles only. | The book skills |

The last column is the point. A correction that's true about me everywhere went to memory. A correction about one kind of work went to that skill. The ones that cost me most (the em dashes, that first banned line) got a line in the linter, so a machine catches them before I do.

## Your turn

1. **Start the file.** Create `logs/corrections.md` with this header:
   ```
   # Corrections
   | Date | What it did | What it should do | Where it went |
   |---|---|---|---|
   ```

2. **Fill in the first five.** Think back over your conversations so far. What have you corrected more than once? Write five rows. Leave the last column blank for now.
   - _____
   - _____
   - _____
   - _____
   - _____

3. **Sort them.** For each row, ask Chapter 12's questions: true about me everywhere (memory), about one kind of task (a skill, Part B), or true only in one project (that project's instructions)? Fill in the last column with where it should go, even if you haven't put it there yet.

4. **Move the first one.** Take the correction that's bitten you most. If it's a memory item, give it to the tool now ("Remember: never..."). If it's a skill item, keep it; B1 will have a Rules section waiting for it.

5. **Set the habit.** Finish this sentence and put it where you'll see it: "When I correct the tool and I've corrected it before, I ______ within ______." (Mine: add a row the same day.)
   _____

*How to: nothing to install; the log is an .md file in your folder (Worksheet 0.3). Memory items go in through a conversation ("Remember this:") or Settings > Memory; skill items go into the Rules section of the skill's `SKILL.md`; project items go into the project's instructions. Worksheet 0.4 has the locations as of October 20, 2026.*

## Why this compounds

The log is the raw material for everything in Part B. Every rule in your first skill comes from a row here, and every row you add is a correction you'll make once instead of forever. After three months, read the log top to bottom: it's a record of the tool learning you, written by you.
