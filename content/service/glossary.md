# Civilian glossary

Plain definitions for the back matter, added as chapters coin them. One or two sentences each. No jargon in the definition of jargon. Note the chapter that introduces each term.

| Term | Plain meaning | Chapter |
|---|---|---|
| Prompt | What you type to it. The whole message, not a magic phrase. | 1 |
| Context | What it knows about you and the task when it answers. You supply most of it. | 1 |
| Model | The AI itself, the thing doing the thinking. Different models have different strengths; the one you're talking to has a name (Claude). | 1 |
| Hallucination | When it states something false with full confidence. It isn't lying; it's filling a gap with what sounds right. | 3 |
| Source | Where a fact came from. Ask for one, then open it. | 3 |
| Draft | What you should ask for instead of a finished product. You edit the draft; that's the job. | 4 |
| Web search | When it looks things up live instead of answering from what it learned in training. Ask for it when facts matter. | 6 |
| Artifact | A document, page, or app it builds for you that you can keep, edit, and share. | 10 |
| Memory | Things it remembers about you between conversations, once you've told it. | 11, 12 |
| Project | A separate room with its own instructions and files, so work on one thing doesn't bleed into another. | 11, 12 |
| Skill | Instructions you write once for a repeat task, so next time you just name the task. It is never finished; every correction you'd otherwise repeat goes into it. | 5 |
| AI tell | A habit of phrasing that gives away machine-written text: the smooth rhythm, the stock line, the inflated word. | 4 |
| Agent | An AI with a job, a name, tools it's allowed to use, and a boundary it can't cross. | 14 |
| Harness | The scaffolding that lets an AI do work rather than just talk: the tools it can call, the memory it keeps, the loop that lets it try again. The model is the engine; the harness is the car. | 14 |
| Brief (or spec) | The written description a coding agent builds from: who it's for, what it does, what it must never do. | 15 |
| Coding agent | An AI that writes and runs software from your brief. | 15 |
| Vibe coding | Building software by telling a coding agent what you want in plain language, looking at what comes back, and asking for changes, instead of writing the code yourself. | 15 |
| Conversation (or thread) | One room. Everything you say in it stays in it; a new conversation starts with a clean slate unless memory, a project, or a skill carries context in. | 11 |
| Model release | A new version of the AI, with a new name and sometimes different habits, replacing the one you were talking to. Your rules don't change; re-test your skills. | 11 |
| Cowork | The name, for a while, of the part of Claude that did longer work: multi-step jobs, file handling, tasks that kept running while you were away. Those capabilities are now part of Claude itself and the separate name is gone. If something tells you to open Cowork, it's out of date. | 11 |
| Brief | What you give the tool before you ask for anything: who it's for, what good looks like, what you already know, what to avoid. Four hundred words beats four. | 1 |
| Brand (for the tool) | Who your company is and what it stands for, written down as rules the tool checks every output against. The colors and type are derived from it, not the other way around. | 8 |
| Standard (outside) | A published guide, checklist, or essay on how to do a kind of work well, which you ask the tool to grade your draft against. | 10 |
| The three-minute test | Put away the materials and explain your argument, succinctly and convincingly, in three minutes or less. If you can't, you haven't finished the work. | 6 |
| Human-centered, human-led superintelligence | The arrangement this book recommends: the intelligence is the machine's, the center and the lead are yours. "I built" means I decided, directed, checked, and owned it. | Introduction |
